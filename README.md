# 第九號病人・讀本與全結局

Larch 平台上的視覺小說《[第九號病人](https://larch.ink/play/market/e1519bf9-dbc8-4830-9873-3ae50416d955)》（作者 QIYUN）的讀本與攻略網站。
主線照順序讀下去，遇到分歧就地展開別條路，十一個結局的圖與走法另外列一份。全作八千多字，讀完大約二十五分鐘。

站在 <https://yazelin.github.io/patient-9-guide/>

## 為什麼做這個

好作品應該更容易被看見。

《第九號病人》要一直點、一直選，選錯就死，所以有些人不會走到最後那段回憶。這一頁讓那些人也看得完，
然後回去玩：站上二十多個連結指回 Larch 的原作頁、作者頁與挑戰賽專區，首屏第一顆按鈕就是「去 Larch 玩《第九號病人》」，
另外有一節寫為什麼這部值得花一小時。

這部作品已經被分享出去了，這就是這個 repo 的目的。上一次是幫陳怡珊的《鴨子探索：是誰？》做的，
在 [duck-who](https://yazelin.github.io/duck-who/)。

製作過程中的查證與修訂（含 2026-09-18 的一段插曲、2026-09-20 依作者意見的修訂）記在 [docs/製作紀錄.md](docs/製作紀錄.md)。

## 怎麼跑

網站是純靜態的，沒有建置步驟。開 `index.html` 就會動（`data/story.js` 讓 `file://` 也讀得到資料）。

    python3 -m http.server 8000     # 或任何靜態伺服器

## 內容怎麼收的

《第九號病人》公開在 Larch 市集上，免登入就能玩，發佈的那個版本也是公開的。
這個站的每一句都對著那個版本核對過，不是憑印象寫的，所以不會漏段或記錯。

    python3 tools/build.py          # 線上抓一份，整理成 data/story.json 與 data/story.js
                                    # Windows 請先設 PYTHONUTF8=1，不然預設編碼（cp950）會讀不了檔案
    python3 tools/fetch_images.py   # 把用到的圖縮成寬 1000 的 WebP 放進 img/
    python3 tools/build.py          # 再跑一次，把圖的網址換成本地縮圖並補上尺寸

`tools/build.py` 做的事：

- 把 422 張卡片與 524 條連線還原成一張圖，從開場卡開始走。
- 能直走的接下去，一個出口接多張卡的地方就是分歧（全作 13 處）。
- **每張卡只會被放進一個段落**：主線先走，其他選項各自成一段，撞到已經寫過的卡就標「接回主線」。
  所以那份全文剛好把作品讀完一次，不多也不少。
- 玩家點背包用道具的卡片是自己連自己的，真正的去向寫在發道具那張卡的 `storyNodeId`，工具會把兩邊接起來。
- 結局的走法取最短路徑，再逐一檢查路上每個選擇：其他選項也走得到同一個結局的話，那一步就不算關鍵，表上不列。
- **結局算 11 個，不是 9 個。** 圖上有 9 張走得到的終點卡，但「爬上天窗」分成三個版本（只有你／帶著贏黎清／連龍傲天一起），
  全部接回同一段回憶與最後的預告圖；作者的更新日誌也寫「已有10幾種結局」。三個版本的起點在 `ESCAPES` 手選，
  各自算出關鍵選擇，輸出在 `data/story.json` 的 `variants`。

輸出跑完會印一行對帳：卡片幾張、寫進幾張、走不到幾張、幾個段落、終點幾個、結局幾個（含天窗幾個版本）。

## 圖

作品插圖原檔一張約 2 MB、五十幾張超過 100 MB，所以 repo 裡放的是縮到寬 1000 的 WebP 副本（合計約 4 MB），
原始網址記在 `img/sources.json`。
