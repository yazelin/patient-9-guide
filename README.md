# 第九號病人・讀本與全結局

Larch 平台上的視覺小說《[第九號病人](https://larch.ink/play/market/e1519bf9-dbc8-4830-9873-3ae50416d955)》（作者 QIYUN）的讀本與攻略網站。

做這個的理由是：這部作品要一直點、一直選，而且選錯就死，所以不玩遊戲的人幾乎不可能把它看完。
這個站把整部作品攤平——主線照順序讀下去，遇到分歧就地展開別條路，九個結局的圖與走法另外列一份。
全作八千多字，讀完大約二十五分鐘。

## 這個 repo 現在是 private，2026-09-20 之前不要開 Pages

作者在市集說明裡寫，完整攻略她自己會在 **2026-09-20** 放到留言區；另外到 2026-09-18 為止還有前三名通關送圖的活動。
在那之前把這份東西公開，等於搶在作者前面把答案貼出去，也會影響活動。

所以：**2026-09-20 之前 repo 保持 private、Pages 不開。**（2026-09-18 曾經開過一次 Pages，同日關掉並改回 private。）
到期之後如果要公開，順手做一件事：作者的攻略貼出來以後，在站上補一個連到她那份的連結。

這一份的定位是收藏與讀本，不是取代原作的攻略站——整站有七個入口連回 Larch 的原作頁
（導覽列、首屏、結局區開頭、想自己玩那一節、故事讀完的那一塊，以及頁尾兩處），
目的是讓看完的人去玩，不是讓人看完就不用玩。

## 怎麼跑

網站是純靜態的，沒有建置步驟。開 `index.html` 就會動（`data/story.js` 讓 `file://` 也讀得到資料）。

    python3 -m http.server 8000     # 或任何靜態伺服器

## 資料是怎麼來的

Larch 市集上的公開作品可以免登入拿到整份專案 JSON，這個站的每一個字都是從那份資料生出來的，
沒有手抄，所以不會漏段或看錯。

    python3 tools/build.py          # 線上抓一份，整理成 data/story.json 與 data/story.js
    python3 tools/fetch_images.py   # 把用到的圖縮成寬 1000 的 WebP 放進 img/
    python3 tools/build.py          # 再跑一次，把圖的網址換成本地縮圖並補上尺寸

`tools/build.py` 做的事：

- 把 422 張卡片與 524 條連線還原成一張圖，從開場卡開始走。
- 能直走的接下去，一個出口接多張卡的地方就是分歧（全作 13 處）。
- **每張卡只會被放進一個段落**：主線先走，其他選項各自成一段，撞到已經寫過的卡就標「接回主線」。
  所以那份全文剛好把作品讀完一次，不多也不少。
- 玩家點背包用道具的卡片是自己連自己的，真正的去向寫在發道具那張卡的 `storyNodeId`，工具會把兩邊接起來。
- 結局的走法取最短路徑，再逐一檢查路上每個選擇：其他選項也走得到同一個結局的話，那一步就不算關鍵，表上不列。

輸出跑完會印一行對帳：卡片幾張、寫進幾張、走不到幾張、幾個段落、幾個結局。

## 圖

作品插圖原檔一張約 2 MB、五十幾張超過 100 MB，所以 repo 裡放的是縮到寬 1000 的 WebP 副本（合計約 4 MB），
原始網址記在 `img/sources.json`。
